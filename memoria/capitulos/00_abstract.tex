% The constant technological advancement and the inherent complexity of academic research demand that computer science laboratories have efficient and secure management of their hardware and software infrastructure. Historically, the laboratory that is the subject of this Bachelor's Thesis has operated under a decentralized, native-execution model, where user administration, permission assignment on machines, fixed-asset inventory control, and the provisioning of environments for researchers were carried out in a fundamentally manual way or through ad-hoc agreements via other platforms. This traditional approach introduces operational deficiencies and complexity.

The technological advanced and the complexity of the technological systems nowadays influence investigation laboratories. The laboratory studied in this Bachelor's degree manages all the information about users, services and the inventory in a manual way without any defined protocol. This approach introduces complexity and operative risks.

To solve this problem, this proyect proposes a design, implementation of a web-based resorce management making a single source of true  of knowledge for the laboratory based on Software Engineering. It also integrates a module for the management and processing resources requests.

% To address this problem, this project proposes the design, development, and implementation of a web-based resource management and service provisioning platform grounded in Software Engineering principles. The main objectives of the solution focus on the comprehensive optimization of inventory while centralizing the knowledge about the use of tools and servers as well as on the automation of the user lifecycle through automated processes for account provisioning, modification, and deactivation upon the conclusion of their institutional affiliation. Additionally, the system integrates a module for the management and processing of resource and access assignment requests.

The development lifecycle was guided by a methodology structured around four incremental iterations, which ensured a controlled and progressive transition from the initial analog state to the final solution. The analytical foundation of the project was built on the methodology known as AS-IS / TO-BE analysis. During the AS-IS phase, the laboratory's current processes were modeled, identifying potential bottlenecks in request handling and the security risks stemming from native provisioning. Based on this diagnosis, the TO-BE model was designed, defining the architecture, automation workflows, and the set of functional and non-functional requirements the platform needed to satisfy. Following this roadmap, the first iteration focused on requirements engineering and technical specification; the second addressed the design, development, and deployment of the architectural core; the third centered on the virtualized development environment for staff; and the fourth and final iteration was oriented toward the theoretical study and practical implementation of third-party tool integrations.

The proposed software solution adopts an architectural pattern orchestrated via Docker, this design decision ensures portability and scalability. Within this modular infrastructure, the persistence layer is divided into two independent containers. The first hosts a relational database responsible for persistently storing structured information, while the second container is dedicated to the management of block-structured data. Above the persistence layer sits the business logic, consisting of an API that implements the Model-View-Controller architectural pattern. This API processes client requests.

To ensure the system's responsiveness and performance when executing computationally intensive tasks like PDF document generation the API delegates these processes to a container acting as an independent worker, communicating through a Redis message queue as a fast and fluid messaging system for message passing, maintained in a separate container. The final module is the frontend, responsible for serving information to users.
In the area of providing a secure and virtualized development environment for researchers, the integration of code-server tools is achieved through per-user access via an Nginx reverse proxy. This approach avoids dependency conflicts and issues arising from native access.

With the deployment of this system, improvement is expected in system administrators workflows through a unified inventory and task management panel across the different servers, reducing management overhead. For researchers, they will make use of a virtual environment that prevents dependency conflicts and guarantees a stable, secure, and remotely accessible workspace.

Finally, this project lays the groundwork for future expansion. First, a future integration of the system with an Apache web server is proposed, enabling administrators and researchers to start, stop, and control the various services running on the server directly from the platform's graphical interface. Second, the addition of an advanced security layer to the request management system is proposed.
